# Development Guidelines

## Commenting

- Comments should only be used UNLESS ABSOLUTELY NECESSARY:
  - DO NOT write comments to explain WHAT the code does
  - ALWAYS prefer to use well-named variables and functions so the code is self-documenting
  - Add comments ONLY IF the WHY behind the implementation is NON-OBVIOUS
- Comments should be CONCISE and SELF-CONTAINED:
  - DO NOT reference decisions, plans, prior context or repeat the implementation
  - DO NOT cross-reference other parts of the implementation UNLESS the intention or implementation is UNCLEAR without it
  - Strive for SHORTER comments rather than longer ones that goes deep into implementation details
- NEVER include unnecessary, repetitive, or commented-out code
